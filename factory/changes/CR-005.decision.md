# Founder Decision — CR-005

Date: 2026-11-02

I approve **Option A** — adopt the lenient reading of the base-move rule:
§14.2 precondition 3 holds while the recorded `base_commit` is still an ancestor
of the base branch (`base_intact` is true), and fails only when the base was
**rewritten** (the recorded commit is no longer reachable). A forward move no
longer invalidates the pending handoff.

This is not a one-predicate fix. The strict reading is stated in three further
places, and they must be corrected in the same change or the pack stays
self-contradictory:

- `reference/validator.md:359-363` — "A base that moved forward has moved"
  (this is the contract `validate.mjs` implements)
- `reference/state-machine.md:96` — invariant 6
- `reference/recovery.md:47` — "Invalidate the approval and re-evaluate"

`approval.md:105` ("has not moved **unexpectedly**"), its four-case staleness
table, and `isolation.md:42` already say what Option A makes the code say.
