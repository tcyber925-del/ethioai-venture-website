# CR-007 — `repairing` → `reviewing` is an unconditional bypass that re-opens the CR-006 hole

**Status: OPEN — needs a founder decision.** Raised 2026-11-02 while implementing
ENG-116 (CR-006 Option C), on the advisory review of PR #48.

## What the review found

`reference/state-machine.md:41` and `transitions.mjs` carry two rows out of
`repairing` with the **same trigger text** and different destinations:

| From | To | Trigger (as written) | Predicate |
| --- | --- | --- | --- |
| `repairing` | `verifying` | the repair was driven by a review `CHANGES` verdict, so the gate re-runs … | gated (build.md READY, clean tree, HEAD on branch, no protected path) |
| `repairing` | `reviewing` | the repair was driven by a review `CHANGES` verdict, so the round re-runs (CR-002) | **unconditional** — always satisfied |

The CR-002 fix added `repairing` → `reviewing` so a review repair was not a dead
end. CR-006's own record identifies that row as the route that *skipped* the
gate. Option C added `repairing` → `verifying` beside it rather than replacing
it.

## Why it matters

A reader keying off the trigger (the pack says "the wording of the trigger is
the specification") sees two identical triggers pointing at two destinations,
one of which re-gates and one of which does not. An orchestrator that takes the
`repairing` → `reviewing` row for a diff-changing repair reproduces exactly the
CR-006 defect — a stale package — which then surfaces at `reviewing` →
`awaiting_human_review` (part B) or, if the package is unreadable, only at the
handoff. Part B makes it *caught*, not *impossible*.

## Options

- **A — retire `repairing` → `reviewing`.** Every review repair goes
  `repairing` → `verifying` → `reviewing`. One route, always re-gated. Costs a
  gate re-run for a repair that did not change the diff (rare: a repair usually
  changes the diff).
- **B — differentiate the triggers.** Keep both rows but give
  `repairing` → `reviewing` a real predicate: the repair did not change the
  diff (`evidence` already names the branch tip). Then the trigger text is
  true and the two rows are distinguishable.
- **C — leave as is.** Part B catches the stale case. Accepted ambiguity, no
  code change.

## Recommendation

Option A is the smallest thing that makes the machine match the prose and
removes the ambiguity; the extra gate run is cheap and only happens when the
CR-002 row is taken. Option B preserves the fast path but needs a new predicate
and its own proof. Not a decision to make silently inside ENG-116 — hence this
CR.

## Boundary

ENG-116 ships Part A + Part B as approved. This CR is **not** implemented there.
No further pack change should be made until the founder chooses.
