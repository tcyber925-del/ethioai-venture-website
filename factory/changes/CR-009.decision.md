# Founder Decision — CR-009

Date: 2026-11-03

I approve **Option A** — EthioBio is removed from the public index listings. The
`/work` index exclusion (ENG-119, already merged) stands, and the homepage
Selected work section is excluded the same way (ENG-120). The approved content
policy is updated so it no longer mandates the listing, which is the
specification update CR-009 named as a precondition.

What this does **not** change: EthioBio remains a routable project. The
canonical detail route `/work/ethiobio` and `src/content/projects/ethiobio.md`
are preserved, and `status: In Development` is unchanged and still mandated by
MIS v1.0. MIS v1.0's evidence rule — that EthioBio be *represented truthfully as
In Development* — is satisfied by the detail page and the content entry. What
was read as a mandate to keep a public **listing** is what this decision
supersedes.

Option B (an explicit `listed: false` front-matter flag) was not taken: the
`projects` schema is a frozen content model (ENG-73), and the existing
`workIndexExcludedSlugs` constant already carries the exclusion as a recorded
decision rather than a deleted entry. Option C (decline as not-reproducible) was
not taken: the founder's annotation stands, and the question is not whether a
duplicate exists but whether EthioBio should be listed.

This is `approval` tier — public content plus a specification change — so it
ships on its own Linear issue (ENG-121) with its own PR, not as a rider on
ENG-119. ENG-119 is already merged; this decision regularises it rather than
re-opening it.

Conveyed in conversation on 2026-11-03; recorded here by the OpenHands agent
that raised the CR. The wording above is the agent's summary of the decision,
not a transcript. Attributing **who** decided it, and amending MIS v1.0 in
Notion, remain founder actions.
