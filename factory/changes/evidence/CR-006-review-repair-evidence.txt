# CR-006 evidence — a review-triggered repair changes the diff but never re-runs the gate

## The walkthrough routes a review repair to step 9 (review), never step 6 (verify)
SKILL.md step 8:

8. **Route a repair.** A job set to `repairing` is re-dispatched by the failure
   source it came from:
   - **A failed check** — set `stage: "building"` and return to step 5 with the
     failing check's output.
   - **A review `CHANGES` verdict** — set `stage: "reviewing"` and return to
     step 9. There is no failed check to hand the builder; the round re-runs
     against the repaired commit.

## fast-gate.md requires the package to correspond to the diff
If a repair changes the diff, every check affected by that change re-runs. The
final package must correspond to the diff submitted for approval.
